## 1. 产品定位

### 1.1 产品简介

**重构智能 ReAgent** 是一个 AI 驱动的营销智能体（Agent）平台，旨在为现代企业提供端到端的**客户洞察、智能推荐与营销自动化**能力。平台融合机器学习与业务规则编排，帮助营销团队从数据中提取价值，以最小人力成本实现精准触达与效果优化。

### 1.2 愿景

让每一个企业都拥有自己的 AI 营销运营团队——7×24 小时持续学习、自动优化、可信任。

### 1.3 目标用户

| 角色 | 描述 | 关键诉求 |
|---|---|---|
| 营销运营人员 | 日常管理营销活动、设置自动化流程 | 低门槛配置、所见即所得、效果可视化 |
| 数据分析师 | 分析客户画像、评估推荐效果 | 灵活查询、多维分析、数据导出 |
| 产品/增长团队 | 搭建推荐策略、A/B 测试 | 快速迭代、AB 框架、数据驱动决策 |
| 技术集成方 | 将 ReAgent 接入自有系统 | 标准化 API、Webhook、事件总线 |
| 系统管理员 | 管理用户权限、配置合规策略 | RBAC、审计日志、GDPR 合规 |

### 1.4 产品边界

- **不含：** 前端 UI 框架之外的自定义页面构建器（Phase 3 考虑）
- **不含：** 原生 CRM/ERP 系统（仅通过 API/Webhook 集成）
- **不含：** NLP 大模型微调（仅调用外部 LLM API）

## 2. 用户角色与故事

### 2.1 营销运营人员 — 林姐

> "我想要创建一个'高价值客户生日特惠'活动，不用写代码，拖拽几个节点就能上线，还能自动跟踪效果。"

- **US-01** 作为营销运营人员，我可以通过可视化工作流编辑器创建营销流程，执行条件分支、定时触发、多渠道分发。
- **US-02** 作为营销运营人员，我可以从预置模板库中选择活动模板并快速自定义，减少重复配置。
- **US-03** 作为营销运营人员，我可以在活动执行中实时查看触达率、转化率等核心指标。

### 2.2 数据分析师 — 小王

> "每个客户的画像太粗糙了，我需要知道哪些客户最近浏览了什么、购买倾向多少分，才能制定差异化策略。"

- **US-04** 作为数据分析师，我可以查看任意客户的完整画像，包括人口属性、行为标签、购买历史、预测评分。
- **US-05** 作为数据分析师，我可以按画像维度（地区、偏好、价值层级）对客户进行分组，导出为 CSV 用于外部分析。

### 2.3 增长产品经理 — 陈哥

> "推荐不准就是浪费流量。我要能快速上线两个推荐策略做 A/B 测试，用数据说话。"

- **US-06** 作为增长产品经理，我可以配置多个推荐策略（协同过滤/基于内容/混合）并分配到不同用户分组进行 A/B 测试。
- **US-07** 作为增长产品经理，我可以在 A/B 测试结束后查看置信区间与统计显著性结论，辅助决策。

### 2.4 技术集成方 — 赵工

> "我们内部有自研 CRM，需要把用户事件实时推给 ReAgent，然后拿推荐结果展示在自建小程序里。"

- **US-08** 作为技术集成方，我可以通过 REST API 获取推荐结果、管理客户画像、触发工作流。
- **US-09** 作为技术集成方，我可以通过 Webhook 接收用户行为事件，触发 ReAgent 内部处理。
- **US-10** 作为技术集成方，我可以通过事件总线监听和发布模块间消息，实现自定义集成。

### 2.5 系统管理员 — 周总

> "数据合规现在不是可选项。所有用户操作必须可审计，GDPR 的数据删除请求必须能一键执行。"

- **US-11** 作为系统管理员，我可以创建和管理用户角色、分配基于角色的访问权限（RBAC）。
- **US-12** 作为系统管理员，我可以查看完整的操作审计日志，追溯每一次数据访问与修改。
- **US-13** 作为系统管理员，我可以配置 GDPR 合规策略（同意管理、数据保留期限、被遗忘权执行）。

## 4. 分阶段计划

### Phase 1 — MVP (当前基线版本 v1.0.0)

**目标:** 构建核心业务闭环，满足小型营销团队的单租户使用需求

**范围:**
- 客户画像引擎：模型定义、CRUD、基本丰富、搜索
- 推荐引擎：协同过滤 + 基于内容 + 混合推荐 + REST API
- 营销自动化：工作流定义与执行、活动管理、基础模板
- 分析仪表盘：核心指标计算、周报/月报导出
- API 网关：统一入口、JWT 认证、RBAC、CORS
- 共享基础设施：配置、缓存、错误处理、日志

**预计工期:** 6-8 周（含测试与修复）
**交付物:** 可部署的单体服务包（FastAPI + Python 后端）

### Phase 2 — 高级 AI 与集成 (规划中)

**目标:** 引入深度学习增强推荐准确性，建立合规与集成能力

**范围:**
- 深度学习协同过滤模型
- 模型版本管理与 A/B 测试框架
- 仪表盘 Widget 与 WebSocket 实时刷新
- Webhook 接收器与事件总线
- GDPR 合规模块（同意管理、审计日志、数据保留）
- 批量导入导出
- A/B 测试活动类型

**前置依赖:** Phase 1 稳定运行 1 个月以上，有足够推荐日志积累

### Phase 3 — SaaS 多租户 (远期规划)

**目标:** 实现多租户架构，支持企业级部署与市场扩展

**范围:**
- 多租户数据隔离
- 租户级配置
- 计费与用量计量
- 节点执行器插件市场
- 多维分析能力
- 自定义仪表盘
- SLA 监控与告警
- 多语言/多时区支持

## 7. 非功能性需求

### 7.1 性能

| 指标 | 目标 |
|---|---|
| API P95 响应时间 | ≤ 500ms (推荐接口 ≤ 200ms) |
| 推荐结果生成 | ≤ 100ms（缓存命中） |
| 并发支持 | ≥ 100 QPS（单实例） |
| 数据处理延迟 | 事件入库 ≤ 5s |

### 7.2 可用性

| 指标 | 目标 |
|---|---|
| 系统可用性 | ≥ 99.5%（Phase 1），≥ 99.9%（Phase 3） |
| 计划内维护通知 | 提前 48 小时 |
| 故障恢复 | ≤ 30 分钟 |

### 7.3 安全

| 要求 | 说明 |
|---|---|
| 认证 | JWT + API Key 双通道 |
| 授权 | 基于 RBAC 的细粒度权限控制 |
| 传输加密 | 全链路 HTTPS |
| 敏感数据 | 客户 PII 字段支持加密存储 |

### 7.4 可观测性

| 维度 | 实现方式 |
|---|---|
| 日志 | 结构化 JSON 日志（Logstash 兼容） |
| 指标 | Prometheus 指标暴露（/metrics） |
| 追踪 | OpenTelemetry 支持（Phase 2） |
| 告警 | 关键指标异常自动通知 |

### 7.5 兼容性

| 内容 | 说明 |
|---|---|
| Python 版本 | 3.10+ |
| 数据库 | PostgreSQL 14+（核心）、Redis 7+（缓存） |
| 部署方式 | Docker 容器化（Phase 1）、Kubernetes（Phase 2） |

## 8. 术语表

| 术语 | 说明 |
|---|---|
| 画像 Enrichment | 基于原始行为数据自动补充客户标签与预测评分的过程 |
| 协同过滤 | 基于"相似用户"的偏好模式推断推荐内容 |
| 混合推荐 | 结合多种推荐算法（协同+内容）加权输出最终推荐 |
| 工作流 | 由条件、动作、定时器组成的营销流程 DAG |
| RBAC | 基于角色的访问控制 (Role-Based Access Control) |
| PII | 个人身份信息 (Personally Identifiable Information) |
